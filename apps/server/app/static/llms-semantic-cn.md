# 医院挂号系统 - API 语义描述

> 本文档提供医院挂号系统 API 的语义描述，包括业务上下文、使用模式和端点关系。

## 系统概述

医院挂号系统是一个多租户 SaaS 平台，用于医院预约挂号管理。支持多门店、多科室、多医生的灵活排班。

### 核心业务实体

| 实体 | 说明 | 关键关系 |
|------|------|----------|
| **租户** | 机构/医院 | 拥有多个门店 |
| **门店** | 物理位置/分院 | 拥有科室、医生 |
| **科室** | 医疗科室 | 属于门店，拥有医生 |
| **医生** | 医疗专业人员 | 属于科室，拥有排班 |
| **患者** | 终端用户 | 预约挂号，拥有就诊卡 |
| **预约** | 预约记录 | 关联患者、医生、排班 |
| **排班** | 时段可用性 | 定义医生可用时间 |

### 认证流程

┌─────────────────────────────────────────────────────────────┐

## 业务工作流

### 1. 预约挂号流程

**业务目标：** 患者预约医生的号源

**语义步骤：**
1. **发现** - 患者浏览可用科室和医生
2. **选择** - 患者选择医生并查看可用时段
3. **预约** - 患者创建预约
4. **确认** - 系统确认预约并发送通知

**API 调用序列：**
```
GET  /departments/tree          → 获取科室树
GET  /doctors/by-department/{id} → 列出科室下的医生
GET  /doctors/public/{id}        → 查看医生详情
GET  /schedules/available/{id}   → 获取可用时段
GET  /booking-notices/public     → 查看预约须知
POST /appointments               → 创建预约
```

**关键业务规则：**
- 重复预约检查（同一患者、同一医生、同一时间）
- 需要确认预约须知
- 排班可用性验证

### 2. 患者签到流程

**业务目标：** 患者在医院/门店签到

**语义步骤：**
1. **到达** - 患者到达门店
2. **识别** - 患者扫描二维码或提供预约号
3. **签到** - 系统记录患者到达
4. **排队** - 患者加入等待队列

**API 调用序列：**
```
GET  /stores/{id}/checkin-qrcode     → 获取门店签到二维码
GET  /appointments/today-pending      → 列出今日待签到预约
GET  /appointments/by-no/{no}         → 按预约号查询
PUT  /appointments/{id}/sign-in       → 签到
GET  /appointments/queue              → 查看队列状态
```

### 3. 医生叫号流程

**业务目标：** 医生叫号就诊

**语义步骤：**
1. **查看队列** - 医生查看等待患者
2. **叫号** - 医生呼叫下一位患者
3. **就诊** - 患者就诊
4. **完成** - 医生标记就诊完成

**API 调用序列：**
```
GET  /doctor-portal/queue              → 获取等待队列
GET  /doctor-portal/queue/info         → 获取队列统计
PUT  /appointments/{id}/call           → 叫号
PUT  /appointments/{id}/complete       → 完成就诊
PUT  /appointments/{id}/pass           → 过号
PUT  /appointments/{id}/recall         → 重新叫号
```

### 4. 排班管理流程

**业务目标：** 管理员管理医生排班

**语义步骤：**
1. **模板创建** - 创建排班模板
2. **排班生成** - 从模板生成排班
3. **调整** - 修改个别排班
4. **停诊** - 处理医生不可用情况

**API 调用序列：**
```
GET  /shift-types                      → 获取班次类型定义
POST /schedule-templates               → 创建模板
POST /schedule-templates/generate      → 生成排班
GET  /schedules                        → 列出排班
POST /schedules/batch-suspend          → 批量停诊
POST /schedule-suspensions             → 创建停诊
```

## 按业务域分类的端点

### 用户管理域

**用途：** 用户认证、档案管理、患者管理

**关键端点：**
- `/auth/*` - 认证（登录、注册、微信集成）
- `/users/*` - 用户档案管理
- `/users/patients/*` - 患者（就诊人）管理

**业务上下文：**
- 支持多种认证方式适应不同用户类型
- 患者可以管理家庭成员（老人/儿童）
- 就诊卡集成医院系统

### 医疗资源域

**用途：** 管理医生、科室、门店和诊费

**关键端点：**
- `/doctors/*` - 医生 CRUD 和公开查询
- `/departments/*` - 科室层级管理
- `/stores/*` - 门店/分院管理
- `/consultation-fees/*` - 诊费配置

**业务上下文：**
- 多门店架构支持连锁医院
- 科室层级实现灵活组织
- 公开端点用于患者端查询

### 预约管理域

**用途：** 核心预约和排班功能

**关键端点：**
- `/appointments/*` - 预约生命周期管理
- `/schedules/*` - 排班 CRUD 和查询
- `/schedule-templates/*` - 基于模板的排班
- `/shift-types/*` - 班次类型定义

**业务上下文：**
- 基于模板的排班减少管理员工作量
- 批量操作提高管理效率
- 基于规则的预约约束

### 就诊服务域

**用途：** 临床操作和医生端

**关键端点：**
- `/doctor-portal/*` - 医生专属操作
- `/medical-records/*` - 患者病历
- `/appointments/{id}/call|complete|pass` - 队列管理

**业务上下文：**
- 医生端用于队列管理
- 病历集成
- 实时队列状态更新

### 内容通知域

**用途：** 内容管理和用户通知

**关键端点：**
- `/news/*` - 新闻文章
- `/notices/*` - 系统公告
- `/banners/*` - 横幅管理
- `/messages/*` - 用户消息

**业务上下文：**
- 多渠道通知支持
- 内容定时发布
- 用户反馈收集

### 数据分析域

**用途：** 商业智能和报表

**关键端点：**
- `/statistics/appointments` - 预约统计
- `/statistics/revenue` - 收入分析
- `/statistics/departments` - 科室绩效
- `/statistics/doctors` - 医生绩效

**业务上下文：**
- 实时仪表盘数据
- 趋势分析和预测
- 绩效基准对比

### 系统管理域

**用途：** 系统配置和管理

**关键端点：**
- `/permissions/*` - 权限管理
- `/roles/*` - 基于角色的访问控制
- `/settings/*` - 系统设置
- `/audit-logs/*` - 审计日志

**业务上下文：**
- 多租户配置
- 细粒度权限控制
- 合规和审计支持

## 错误处理模式

### 常见错误响应

| 代码 | 含义 | 典型原因 |
|------|------|----------|
| 0 | 成功 | 操作完成 |
| 400 | 请求错误 | 参数无效 |
| 401 | 未认证 | Token 缺失/无效 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 未找到 | 资源不存在 |
| 409 | 冲突 | 重复预约 |
| 422 | 验证错误 | 业务规则违反 |
| 500 | 服务器错误 | 内部错误 |

### 业务错误代码

| 代码 | 含义 | 恢复操作 |
|------|------|----------|
| 1001 | 排班不可用 | 选择其他时间 |
| 1002 | 重复预约 | 先取消现有预约 |
| 1003 | 预约次数达上限 | 等待下一周期 |
| 1004 | 医生不可用 | 选择其他医生 |
