# 医院挂号系统

> 一套完整的医院预约挂号解决方案，支持多门店、多科室、多医生的排班预约管理。

- API Version: 1.0.0
- Base Path: /api/v1
- Authentication: Bearer Token (JWT)

---

## 认证

### POST /api/v1/auth/login

**用户登录**

用户通过手机号和密码登录系统。

**功能说明：**
- 验证用户手机号和密码
- 检查账号状态是否正常
- 生成访问令牌和刷新令牌
- 返回用户基本信息

**请求示例：**
```json
{
  "phone": "13800138000",
  "password": "password123"
}
```

**响应示例：**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600,
  "user": {
    "id": "user_123",
    "phone": "13800138000",
    "nickname": "张医生",
    "avatar": "https://example.com/avatar.jpg",
    "gender": 1,
    "status": 1
  }
}
```

**错误响应：**
- 401: 手机号或密码错误
- 403: 账号已被禁用

**Request:**

  - **请求体**: application/json
    - Schema: `LoginRequest`
    - `phone` (string, 必填)
    - `password` (string, 必填)

---

### POST /api/v1/auth/register

**用户注册**

新用户注册账号。

**功能说明：**
- 验证手机号格式和唯一性
- 创建用户账号
- 默认状态为正常
- 注册成功后可直接登录

**请求示例：**
```json
{
  "phone": "13800138000",
  "password": "password123",
  "nickname": "张医生",
  "gender": 1
}
```

**响应示例：**
```json
{
  "id": "user_123",
  "phone": "13800138000",
  "nickname": "张医生",
  "avatar": null,
  "gender": 1,
  "status": 1,
  "created_at": "2024-01-15T10:30:00Z"
}
```

**错误响应：**
- 400: 手机号已注册或格式不正确

**字段说明：**
- phone: 手机号，11位数字，必须唯一
- password: 密码，最少6位
- nickname: 昵称，可选
- gender: 性别，0-未知, 1-男, 2-女

**Request:**

  - **请求体**: application/json
    - Schema: `RegisterRequest`
    - `phone` (string, 必填)
    - `password` (string, 必填)
    - `code` (any, 可选)

### POST /api/v1/auth/send-code

**发送验证码**

发送短信验证码

**功能说明**：

    - `phone` (string, 必填)
    - `codeType` (string, 可选)

### POST /api/v1/auth/forgot-password

**忘记密码**

通过手机号和验证码重置密码

**功能说明**：
- 验证手机号和验证码
- 重置用户密码
- 无需旧密码即可重置

**请求示例**：

- 密码长度 6-20 位

**Request:**

  - **请求体**: application/json
    - Schema: `ForgotPasswordRequest`
    - `phone` (string, 必填)
    - `verificationCode` (string, 必填)
    - `newPassword` (string, 必填)

## 门店管理

### GET /api/v1/stores/by-code/{code}

**获取门店**

通过门店编码获取门店信息（公开接口，无需登录）。

    **适用场景**：患者端 H5/小程序初始化时验证门店。

    **参数说明**：
    - code: 门店编码（路径参数）

    **业务规则**：
    - 已停业（status != 1）的门店返回 400 错误

**Parameters:**

  - `code` (path, string, 必填)

---

### GET /api/v1/stores/check-unique

**检查唯一性**

检查门店名称或编码是否已存在，用于前端表单实时校验。

    **参数说明**：
    - field: 检查字段，可选 "name"（名称）或 "code"（编码）
    - value: 字段值
    - exclude_id: 编辑时排除当前门店ID（可选）

    **返回数据**：
    - { "exists": bool } - 是否已存在

**Parameters:**

  - `field` (query, string, 必填) - 检查字段: name 或 code
  - `value` (query, string, 必填) - 字段值
  - `exclude_id` (query, any, 可选) - 排除的门店ID（编辑时使用）

---

### GET /api/v1/stores

**获取门店列表**

获取门店列表（管理端），支持分页和筛选。

    **支持筛选条件**：
    - keyword: 关键字搜索（名称/地址）
    - status: 按状态筛选（0=停业 1=营业 2=禁用）
    - city: 按城市筛选

    **数据隔离**：
    - 门店管理员只能看到自己关联的门店（不分页，直接返回全量）
    - 超级管理员可看到所有门店（分页）

    **返回数据**：
    - 包含每个门店的科室数量（department_count）

**Parameters:**

  - `keyword` (query, any, 可选)
  - `status` (query, any, 可选)
  - `city` (query, any, 可选)
  - `page` (query, integer, 可选)
  - `page_size` (query, integer, 可选)

---

### PATCH /api/v1/stores/{store_id}/status

**更新门店状态**

更新门店营业状态。

    **参数说明**：
    - store_id: 门店ID（路径参数）
    - status: 新状态值（0=停业 1=营业 2=禁用）

    **权限规则**：
    - 停业(0)/营业(1): 门店管理员可操作（限本门店）
    - 禁用(2): 仅超级管理员可操作，禁用后该门店所有人员无法登录
    - 从禁用状态恢复: 仅超级管理员可操作

**Parameters:**

  - `store_id` (path, string, 必填)
  - `status` (query, integer, 必填) - 状态: 0-停业 1-营业 2-禁用

## 预约查询

### GET /api/v1/appointments/query

**获取预约列表**

获取当前租户下的预约列表，支持分页和多条件筛选。

    **支持筛选条件**：
    - status: 按状态筛选（0=待支付 1=已预约 2=已签到 4=就诊中 5=已完成 6=已取消 7=已过期/过号 8=已爽约；3 为历史遗留状态）
    - doctor_id: 按医生筛选
    - department_id: 按科室筛选
    - patient_id: 按患者筛选
    - store_id: 按门店筛选
    - start_date / end_date: 按排班日期范围筛选
    - created_start / created_end: 按创建时间范围筛选
    - keyword: 关键字搜索（预约编号/患者姓名/手机号）

    **分页规则**：
    - 默认 page_size=10，常规上限 100
    - page_size > 100 时需要管理员权限，且必须提供 start_date 和 end_date

    **数据隔离**：
    - 管理员可查看所有预约（门店管理员仅查看本门店）
    - 普通用户只能查看自己的预约

**Parameters:**

  - `status` (query, any, 可选)
  - `patient_id` (query, any, 可选)
  - `store_id` (query, any, 可选)
  - `start_date` (query, any, 可选)
  - `end_date` (query, any, 可选)
  - `keyword` (query, any, 可选)
  - `doctor_id` (query, any, 可选)
  - `department_id` (query, any, 可选)
  - `created_start` (query, any, 可选)
  - `created_end` (query, any, 可选)
  - `page` (query, integer, 可选)
  - `page_size` (query, integer, 可选)

---

### GET /api/v1/appointments/query/today

**获取今日预约**

获取当前医生今日的所有预约列表（医生端专用）。

    **业务规则**：
    - 仅返回当前登录医生今日的预约
    - 需要通过 Token 识别医生身份（doctor_id）
    - 每条预约包含 isFollowUp 字段，标记是否为复诊患者

    **返回数据**：
    - 包含患者基本信息、预约编号、排班时间、状态流转时间等
    - 复诊判断基于患者在该医生/科室的历史就诊记录

---

### GET /api/v1/appointments/query/today-pending

**获取今日待签到预约**

获取当前用户在指定门店的今日待签到预约（患者端专用）。

    **适用场景**：患者扫码签到时选择要签到的预约。

    **参数说明**：
    - store_id: 门店ID（必填），用于筛选该门店下的待签到预约

    **返回数据**：
    - 包含签到状态判断（signInStatus）：available（可签到）/ early（未到时间）/ late（已过时间）/ error（异常）
    - signInMessage: 签到状态对应的提示信息
    - 通过规则引擎计算签到时间窗（checkinOpenAt / checkinCloseAt）
    - minutesUntilOpen / minutesUntilClose: 距离签到开放/截止的剩余分钟数

**Parameters:**

  - `store_id` (query, string, 必填) - 门店ID

---

### GET /api/v1/appointments/query/queue

**获取签到队列**

获取当日已签到的患者队列，按签到时间排序。

    **适用场景**：管理后台和医生端查看当日叫号/就诊队列。

    **参数说明**：
    - store_id: 按门店筛选（可选）
    - doctor_id: 按医生筛选（可选，医生端自动取当前医生）
    - target_date: 指定日期（可选，默认今日）

    **业务规则**：
    - 医生端只能查看自己的队列（通过 Token 识别医生身份）
    - 管理员可查看任意医生/门店的队列
    - 返回数据包含签到方式（checkinMethod），如手动签到、扫码签到等

**Parameters:**

  - `store_id` (query, any, 可选)
  - `doctor_id` (query, any, 可选)
  - `target_date` (query, any, 可选)

### POST /api/v1/tenants/{tenant_id}/migrate

**跨租户数据迁移**

将源租户的配置类数据迁移到目标租户，仅限平台管理员操作。

**支持迁移的实体类型：**
- stores: 门店
- departments: 科室
- doctors: 医生
- schedule_templates: 排班模板
- doctor_booking_settings: 医生预约设置
- booking_notices: 预约须知
- email_templates: 邮件模板
- message_templates: 消息模板
- rest_days: 休息日
- blacklists: 黑名单
- store_visit_type_configs: 门店复诊规则配置
- store_email_recipients: 门店邮件接收人
- consultation_fee_templates: 诊费模板
- rule_sets: 规则组（含 windows、booking_policy、checkin_policy、capacity_policy、shift_types 关联）

**配额检查：**
- 迁移前会自动检查目标租户的门店数和医生数配额是否足够
- 如果配额不足，返回 400 错误

**ID 处理：**
- 默认生成新的 UUID，避免冲突
- 设置 preserve_ids=true 可保留原始 ID（需谨慎使用）

**请求示例：**
```json
{
  "sourceTenantId": "tenant_abc123",
  "preserveIds": false,
  "entityTypes": ["stores", "departments", "doctors"]
}
```

**响应示例：**
```json
{
  "targetTenantId": "tenant_xyz789",
  "sourceTenantId": "tenant_abc123",
  "durationMs": 1250,
  "copied": {
    "stores": 2,
    "departments": 5,
    "doctors": 10
  },
  "failures": []
}
```

**Parameters:**

  - `tenant_id` (path, string, 必填)

**Request:**

  - **请求体**: application/json
    - Schema: `TenantMigrateRequest`
    - `sourceTenantId` (string, 必填)
    - `preserveIds` (boolean, 可选)
    - `entityTypes` (any, 可选)

### POST /api/v1/refunds/wechat/callback
