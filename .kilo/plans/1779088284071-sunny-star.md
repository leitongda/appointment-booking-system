# `apps/admin/config` 配置重构方案

## 目标

把 `apps/admin/config/` 下扁平、臃肿、且彼此存在重复/分散的配置，按照「常量 → 环境 → 子领域配置 → 装配入口」的层次重新组织，主要价值：

1. `config.ts` 从 246 行（混杂 layout / webpack / mfsu / codeSplitting）瘦身为「装配入口」，仅做组合。
2. `routes.ts`（472 行）按业务域拆解，新增/修改某个域的路由不再触动一个巨大文件。
3. `appConfig.ts` + `defaultSettings.ts` + `process.env` 读取统一到 `constants/` + `env.ts`，消除重复并统一来源。
4. `proxy.ts` 用工厂函数消除三套环境的重复定义。
5. 顺带修复几个已经明显存在的不一致 / 缺漏。

## 现状梳理

| 文件 | 行数 | 主要职责 | 现存问题 |
| --- | --- | --- | --- |
| `config.ts` | 246 | umi defineConfig 入口，包含 alias/define/layout/codeSplitting/chainWebpack/mfsu/links 等 | 单文件耦合多种关注点；`layout` 与 `defaultSettings.ts` 字段重复且 `colorPrimary` 不一致（`#722ED1` vs `#1677ff`）；splitChunks 的 cacheGroups 定义占 100+ 行 |
| `appConfig.ts` | 16 | 导出 `APP_TITLE`、`DEFAULT_LOGO` | 注释掉的旧标题未清理；与 `defaultSettings.ts` 一起被两处独立引用 |
| `defaultSettings.ts` | 32 | ProLayout 默认设置 | 与 `config.ts` 中 layout 字段几乎重复；`colorPrimary` 取值不一致；当前实际是否被运行时引用需要在 `src/app.tsx` 等处确认 |
| `proxy.ts` | 51 | dev/test/pre 三套代理 | 三个环境结构重复；`test/pre` 缺少 `_AMapService` 路径；同一目标却写了 3 份 |
| `routes.ts` | 472 | 全部路由（认证/仪表盘/平台/医疗/组织/运营/系统/旧路径重定向/默认路由） | 单文件过长，业务域之间无边界；旧路径重定向块占近 50 行；二级 `redirect` 重复 |

## 目标目录结构

```
apps/admin/config/
├── config.ts                      # 装配入口，瘦身后约 60-80 行
├── proxy.ts                       # 重写为工厂调用，<= 30 行
├── routes.ts                      # 仅做聚合 import + 顺序导出
├── constants/
│   ├── index.ts                   # 桶导出
│   ├── app.ts                     # APP_TITLE、DEFAULT_LOGO、APP_PRIMARY_COLOR 等品牌常量
│   └── env.ts                     # process.env 集中读取（REACT_APP_ENV / API_BASE_URL / PROXY_TARGET / NODE_ENV 判定）
├── layout/
│   ├── index.ts                   # 默认导出 layout 配置（替代 defaultSettings）
│   └── settings.ts                # ProLayoutProps 字段（navTheme/colorPrimary/...）
├── webpack/
│   ├── index.ts                   # 导出 chainWebpack(config) 入口
│   ├── compression.ts             # gzip 预压缩插件配置
│   ├── splitChunks.ts             # splitChunks 总配置 + cacheGroups
│   └── cacheGroups.ts             # 各 cacheGroup 的定义（antd/charts/react/...）
├── build/
│   ├── codeSplitting.ts           # umi codeSplitting 配置
│   ├── mfsu.ts                    # mfsu 配置
│   └── targets.ts                 # 浏览器目标
├── proxy/
│   ├── index.ts                   # 默认导出按环境装配的 proxy
│   ├── createProxy.ts             # createProxy(target, options) 工厂
│   └── rules.ts                   # /api、/uploads、/_AMapService 等通用规则定义
└── routes/
    ├── index.ts                   # 聚合所有路由数组并按顺序导出
    ├── auth.ts                    # /login、/tenant-suspended
    ├── dashboard.ts               # /dashboard
    ├── platform.ts                # 平台管理（租户、订阅计划、小程序平台等）
    ├── medical-services.ts        # 医疗服务（医生/排班/预约/患者/病历/诊费）
    ├── organization.ts            # 组织架构
    ├── operations.ts              # 运营中心
    ├── system.ts                  # 系统管理
    ├── account.ts                 # /account 个人设置
    ├── redirects.ts               # 旧路径重定向（configuration / monitoring / operations.system.settings）
    └── fallbacks.ts               # `/` 重定向 + `*` 404
```

> 说明：`defaultSettings.ts` 不再保留独立文件，统一并入 `layout/`；如有外部 import 引用，会在 `layout/index.ts` 提供同名命名导出兼容。

## 具体抽离方案

### 1. 常量与环境（`constants/`）

- `constants/app.ts`
  - `APP_TITLE`（沿用「管理系统」当前值）
  - `DEFAULT_LOGO`（沿用 `/logo.svg`）
  - 新增 `APP_PRIMARY_COLOR`：暂定保留 `config.ts` 当前生效的 `#722ED1`（以行为一致性优先；将该值同时同步给 `layout/settings.ts`，修复二者不一致问题）
  - `DEFAULT_LAYOUT_LOGO`：保留 config.ts 中的 `https://gw.alipayobjects.com/...` URL（与 DEFAULT_LOGO 区分用途）
- `constants/env.ts`
  - `REACT_APP_ENV`（默认 `'dev'`）
  - `API_BASE_URL`（默认 `'/api/v1'`）
  - `PROXY_TARGET`（默认 `'http://localhost:9000'`）
  - `IS_PROD`：`process.env.NODE_ENV === 'production'` 的派生
  - 全部以 `as const` 导出，方便其他模块（webpack/proxy）共享

### 2. Layout 配置（`layout/`）

- `layout/settings.ts`：把 `config.ts` 中 layout 块的字段（navTheme/colorPrimary/layout/contentWidth/fixedHeader/fixSiderbar/pwa/logo/token/siderMenuType/splitMenus/locale/title）整体迁出，并复用 `constants/app.ts` 的常量
- `layout/index.ts`：默认导出该对象；为兼容潜在外部引用，再 `export { default as Settings } from './settings'`
- 删除 `defaultSettings.ts`（或改为只 re-export `layout/`，二选一）；优先方案：删除 + 在 `layout/index.ts` 命名导出。若 grep 发现仍被 `src/` 引用，则保留为 thin re-export 文件，避免破坏导入路径。

### 3. Webpack / 构建（`webpack/` + `build/`）

- `webpack/cacheGroups.ts`：将 11 个 cacheGroup（antd / proComponents / charts / wangeditor / dndKit / pinyin / imageCrop / html2canvas / react / router / utils / vendors / common / commonStyles）整理为命名常量，便于按需注释 / 调整优先级
- `webpack/splitChunks.ts`：导出 `getSplitChunksConfig()`，组合 cacheGroups 与公共参数（minSize / maxAsyncRequests / ...）
- `webpack/compression.ts`：导出 `applyCompressionPlugin(config)`，封装 `compression-webpack-plugin` 配置
- `webpack/index.ts`：导出 `chainWebpack(config)`，仅做：
  ```ts
  if (IS_PROD) {
    applyCompressionPlugin(config);
    config.optimization.splitChunks(getSplitChunksConfig());
  }
  ```
- `build/codeSplitting.ts`、`build/mfsu.ts`、`build/targets.ts`：把 `codeSplitting`、`mfsu`、`targets` 三个对象搬出来，主要为可读性

### 4. Proxy（`proxy/`）

- `proxy/createProxy.ts`：
  ```ts
  export const createProxy = (
    target: string,
    options?: { rewrite?: boolean; secure?: boolean }
  ) => ({
    target,
    changeOrigin: true,
    secure: options?.secure ?? false,
    ...(options?.rewrite ? { pathRewrite: { '^/api': '/api' } } : {}),
  });
  ```
- `proxy/rules.ts`：声明通用路径常量 `API_PATH = '/api'`、`UPLOADS_PATH = '/uploads'`、`AMAP_PATH = '/_AMapService'`
- `proxy/index.ts`：用工厂装配 dev/test/pre。**顺带修复**：把 `_AMapService` 也加入 test/pre（与 dev 对齐），避免按环境跑联调时缺少地图代理；如不希望增加，将作为可选项在实施时确认（见「待用户最终确认的取舍」）。

### 5. Routes（`routes/`）

- 每个一级菜单（platform / medical-services / organization / operations / system）独立成文件，类型统一为 `RouteConfig[]` 或 umi 的 `IRouteProps[]`
- `routes/redirects.ts`：聚合三大块旧路径重定向（`/configuration/*`、`/monitoring/*`、`/operations/system/settings/*`）
- `routes/auth.ts`、`routes/dashboard.ts`、`routes/account.ts`、`routes/fallbacks.ts` 单独维护，便于改动隔离
- `routes/index.ts`：
  ```ts
  export default [
    ...auth,
    ...dashboard,
    ...platform,
    ...medicalServices,
    ...organization,
    ...operations,
    ...system,
    ...redirects,
    ...account,
    ...fallbacks, // 必须放最后：'/' 与 '*'
  ];
  ```
- 旧 `routes.ts` 改为 `export { default } from './routes/index'`，或直接删除原文件改用 `routes/`（二选一，详见兼容性）
- 顺带轻量整理：每个域文件顶部加注释说明所属业务、access key 一览，便于权限审查

### 6. config.ts 的瘦身入口

最终 `config.ts` 只剩组装逻辑：

```ts
import path from 'path';
import { defineConfig } from '@umijs/max';
import { APP_TITLE } from './constants/app';
import { API_BASE_URL, REACT_APP_ENV } from './constants/env';
import layout from './layout';
import routes from './routes';
import proxy from './proxy';
import codeSplitting from './build/codeSplitting';
import mfsu from './build/mfsu';
import targets from './build/targets';
import chainWebpack from './webpack';

export default defineConfig({
  alias: { '@config': path.resolve(__dirname) },
  define: { 'process.env.API_BASE_URL': API_BASE_URL },
  hash: true,
  antd: {},
  access: {},
  model: {},
  initialState: {},
  request: {},
  layout,
  routes,
  proxy: proxy[REACT_APP_ENV as keyof typeof proxy],
  npmClient: 'pnpm',
  mfsu,
  targets,
  esbuildMinifyIIFE: true,
  title: APP_TITLE,
  favicons: ['/favicon.ico'],
  clickToComponent: {},
  codeSplitting,
  chainWebpack,
  links: [],
});
```

预计行数从 246 降到 ~50。

## 顺带修复的明显问题

按用户选择「可顺带修复明显问题」执行：

1. **`colorPrimary` 不一致**：`config.ts` 用 `#722ED1`，`defaultSettings.ts` 用 `#1677ff`。统一为 `#722ED1`（即当前实际生效值）并集中到 `constants/app.ts.APP_PRIMARY_COLOR`。
2. **`appConfig.ts` 注释行清理**：移除被注释掉的旧标题 `'医院挂号管理系统'`。
3. **`test/pre` 代理补齐 `_AMapService`**：与 dev 对齐，避免环境间行为漂移。
4. **`logo` 字段双源**：`config.ts.layout.logo` 是远程 URL，`defaultSettings.logo` 是 `/logo.svg`。在 `constants/app.ts` 中分别定义 `DEFAULT_LOGO`（本地）与 `LAYOUT_LOGO_URL`（远程），由 `layout/settings.ts` 选用 `LAYOUT_LOGO_URL`，保持当前实际呈现不变。
5. **`defaultSettings` 与 `config.ts.layout` 字段去重**：迁移到 `layout/settings.ts` 后删除冗余文件（或保留 thin re-export，详见兼容性）。

> 不会修复的内容（保持现状）：版权头注释、splitChunks 内部参数取值、antd token 空对象、`pwa: true` vs `false` 的差异（以 `config.ts` 实际值为准 → 统一保留 `pwa: true`）。

## 兼容性与潜在风险

- **`@config` 别名**：保留指向 `apps/admin/config/`，所有新模块仍能通过 `@config/...` 访问，无须改动 `src/` 内引用。
- **`defaultSettings.ts` 外部引用**：实施第一步会通过 `grep "defaultSettings"` 全局搜索，如发现 `apps/admin/src/**` 仍 import，则保留 `defaultSettings.ts` 作为 `export { default } from '../layout';` 的兼容 re-export，避免破坏现有 import。
- **`appConfig.ts` 外部引用**：同样先 grep；推荐做法是保留 `appConfig.ts` 为 re-export `constants/app.ts`，零破坏迁移。
- **`routes.ts` 外部引用**：同上，必要时让 `routes.ts` 仅 re-export `routes/index.ts`。
- **`proxy.ts` 外部引用**：同上处理。
- **行为等价**：除上文「顺带修复」5 点外，所有 webpack / mfsu / targets / codeSplitting 配置值保持 byte-for-byte 一致；splitChunks 不调整任何 priority/test 正则。

## 实施步骤（按提交粒度划分）

1. **建骨架 + 常量**：新建 `constants/`、`layout/`，迁移 `appConfig.ts` 与 `defaultSettings.ts` 内容并加 thin re-export 兜底；同步统一 `colorPrimary` 与 logo 双源
2. **拆 webpack/build**：新建 `webpack/`、`build/`，把 `chainWebpack`、`codeSplitting`、`mfsu`、`targets` 抽离；`config.ts` 改为引用
3. **拆 proxy**：新建 `proxy/`，落地 `createProxy` 工厂；补齐 test/pre 的 `_AMapService`；`proxy.ts` 变 re-export
4. **拆 routes**：新建 `routes/`，按业务域逐个迁出；`routes.ts` 变 re-export；逐域校验路由数量与 access 字段无变化
5. **瘦身 config.ts**：把入口改为纯装配；最终再做一次构建/类型检查
6. （可选）若全局 grep 确认外部无 `defaultSettings.ts` / `appConfig.ts` / 旧 `routes.ts` / `proxy.ts` 引用，则把这些 thin re-export 文件删除收尾

## 验收标准

- `pnpm --filter admin dev` 能启动，菜单、路由、代理、layout 视觉与重构前一致
- `pnpm --filter admin build` 产物结构（chunk 名、数量）与重构前等价；splitChunks 行为不变
- `apps/admin/config/config.ts` 行数 ≤ 80
- `apps/admin/config/routes.ts`（如保留）≤ 5 行（仅 re-export）
- `apps/admin/config/` 顶层文件不再混杂 webpack/layout 业务逻辑
- TypeScript 无新增报错；`@config/...` 别名与 `src/` 现有 import 全部仍可通过

## 待用户最终确认的取舍（如有疑问可在实施前回到本节）

- `colorPrimary` 是否就用 `#722ED1`（当前实际生效值）？
- 是否同意为 test/pre 环境补齐 `_AMapService` 代理？
- 是否倾向保留 `appConfig.ts` / `defaultSettings.ts` / `proxy.ts` / `routes.ts` 这四个旧文件作为 thin re-export 以最大化兼容，还是直接删除并修改 `src/` 中所有 import？（计划默认采用「先保留 thin re-export，最后阶段视引用情况再决定是否删除」的稳妥路径。）
