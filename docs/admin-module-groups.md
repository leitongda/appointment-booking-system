# Admin 端功能逻辑与模块分组

本次自动化测试以 `apps/admin` 为目标，不覆盖 `apps/admin-v2`。原因是当前 `admin-v2` 仅包含登录页与仪表盘，无法代表现有后台完整业务面。

## 1. 仪表盘

- 入口：`/dashboard`
- 逻辑：聚合预约、就诊、患者、医生、收入等核心经营指标，作为后台首页。
- 本轮自动化：验证登录态恢复、首页可达、核心模块入口可正常渲染。

## 2. 平台管理

- 入口前缀：`/platform`
- 子模块：
- 租户管理：租户列表、租户订阅与生命周期管理。
- 订阅计划：SaaS 套餐与计划配置。
- 小程序平台：公司管理、支付配置、小程序实例、模板、构建、发布。
- 本轮自动化：覆盖菜单可达页面，验证 SaaS 平台级页面在超管权限下可稳定打开。

## 3. 医疗服务

- 入口前缀：`/medical-services`
- 子模块：
- 医生管理：医生列表、预约设置。
- 排班管理：规则、排班列表、日历、甘特图、自定义排班、休息日、停诊、停诊审核、统计。
- 预约管理：预约列表、签到队列、预约统计。
- 患者管理：患者列表、就诊卡列表。
- 病历管理：病历浏览与查询。
- 诊费管理：诊费类型、诊费模板。
- 本轮自动化：按页面做 smoke 回归，优先保证核心业务链路页面全部可进。

## 4. 组织架构

- 入口前缀：`/organization`
- 子模块：
- 门店管理：门店列表与门店级配置。
- 科室管理：科室列表与层级管理。
- 医疗配置：预约规则、预约字段、预约须知、就诊卡配置、班次类型、规则组管理。
- 员工管理：后台员工与角色归属。
- 本轮自动化：验证组织配置域页面能在统一 mock 环境下加载。

## 5. 运营中心

- 入口前缀：`/content-center`
- 子模块：
- 内容管理：新闻、公告、轮播图。
- 消息管理：站内消息发送与列表。
- 用户反馈：反馈处理。
- 数据统计：行为与运营分析。
- 本轮自动化：覆盖运营类菜单页，确认富文本/统计类页面至少可完成首屏渲染。

## 6. 系统管理

- 入口前缀：`/system`
- 子模块：
- 角色权限：角色列表与权限分配入口。
- 系统配置：医院信息、微信、邮件、图片、邮件模板、邮件接收人。
- 黑名单管理：患者黑名单配置。
- 系统监控：操作日志、通知日志、签到审计、在线用户。
- 本轮自动化：验证系统治理类页面路由、权限、首屏数据加载流程。

## 自动化测试策略

- 维度：按一级业务域分组，而不是按零散页面分组。
- 颗粒度：本轮为模块级 smoke 测试，不直接覆盖每个页面的深度 CRUD。
- 登录态：通过 Playwright 注入超管会话，避免依赖真实登录流程。
- 数据源：统一拦截 `/api/v1/**` 请求，使用稳定 mock 返回，确保测试可重复执行。
- 断言：以“页面路由可达 + 对应模块标题可见 + 首屏未崩溃”为基线。
