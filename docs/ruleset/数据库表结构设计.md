好的，下面给你一套 **PostgreSQL（推荐 13+）** 的“强结构化”表结构：RuleSet + Window + Policy，支持 **按班次类型配置**，并把“提前多久/是否包含边界/超出如何处理”等全部落库。DDL 都是 PG 风格（`timestamptz、jsonb、check、generated identity` 等）。

> 约定：
>
> * 偏移量统一用 **秒**（`integer`，可为负）
> * 时间统一用 `timestamptz`（避免时区坑）
> * 规则组匹配模式先只做 `FIRST_MATCH`

---

# 1）基础表：班次类型（如你们已有就复用）

```sql
create table shift_type (
  id bigserial primary key,
  code text not null unique,        -- OPD / CHECKUP / EXAM 等
  name text not null,
  enabled boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

# 2）规则组 RuleSet（按班次类型生效）

## 2.1 规则组表

```sql
create table rule_set (
  id bigserial primary key,
  name text not null,
  enabled boolean not null default true,

  -- 先建议只实现 FIRST_MATCH
  match_mode text not null default 'FIRST_MATCH'
    check (match_mode in ('FIRST_MATCH', 'MERGE')),

  priority int not null default 100,         -- 越小越优先

  -- 默认口径（window 可覆盖）
  time_source text not null default 'SERVER'
    check (time_source in ('SERVER', 'CLIENT')),
  timezone_source text not null default 'HOSPITAL'
    check (timezone_source in ('HOSPITAL', 'SHIFT', 'USER')),
  compare_precision text not null default 'SECOND'
    check (compare_precision in ('SECOND', 'MILLISECOND', 'MINUTE')),

  default_open_inclusive boolean not null default true,
  default_close_inclusive boolean not null default true,

  rounding_mode text not null default 'NONE'
    check (rounding_mode in ('NONE', 'FLOOR_TO_MINUTE', 'CEIL_TO_MINUTE')),

  clock_skew_tolerance_sec int not null default 5 check (clock_skew_tolerance_sec >= 0),

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index idx_rule_set_enabled_priority on rule_set (enabled, priority);
```

> `updated_at` 若你们有统一触发器维护更好，这里先保留应用层更新即可。

## 2.2 RuleSet 适用哪些班次类型（多对多）

```sql
create table rule_set_shift_type (
  rule_set_id bigint not null references rule_set(id) on delete cascade,
  shift_type_id bigint not null references shift_type(id) on delete cascade,
  primary key (rule_set_id, shift_type_id)
);

create index idx_rs_st_shift_type on rule_set_shift_type (shift_type_id);
```

**命中逻辑**：按班次的 `shift_type_id` 找 rule_set，`enabled=true`，`priority asc` 取第一条。

# 3）统一动作时间窗：rule_window（BOOK / CHECKIN / CANCEL）

## 3.1 表结构

```sql
create table rule_window (
  id bigserial primary key,
  rule_set_id bigint not null references rule_set(id) on delete cascade,

  action text not null
    check (action in ('BOOK', 'CHECKIN', 'CANCEL')),

  reference_point text not null
    check (reference_point in ('SHIFT_START', 'SHIFT_END', 'BOOKING_CREATED_AT')),

  -- 秒，可为负（提前）；可为正（延后）
  open_offset_sec int not null,
  close_offset_sec int not null,

  -- NULL 表示继承 rule_set 默认值
  open_inclusive boolean null,
  close_inclusive boolean null,

  fail_policy text not null default 'REJECT'
    check (fail_policy in ('REJECT', 'ALLOW_WITH_TAG', 'AUTO_TO_WAITLIST')),
  fail_tag text null,

  enabled boolean not null default true,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  -- 同一 RuleSet 下，每个 action 只允许一条 window
  unique (rule_set_id, action)
);

create index idx_rule_window_rs on rule_window (rule_set_id, enabled);
```

> **offset 的解释**
>
> * `openAt = referenceTime + open_offset_sec`
> * `closeAt = referenceTime + close_offset_sec`
>   例如：提前 7 天开放预约 → `open_offset_sec = -604800`
>   开始前 30 分钟截止预约 → `close_offset_sec = -1800`
>   开始后 15 分钟截止签到 → `close_offset_sec = +900`

# 4）策略 Policy（非时间窗部分）

## 4.1 预约策略 rule_booking_policy

```sql
create table rule_booking_policy (
  rule_set_id bigint primary key references rule_set(id) on delete cascade,

  require_auth boolean not null default true,
  require_patient_profile_complete boolean not null default false,

  per_user_per_shift int not null default 1 check (per_user_per_shift >= 1),
  per_user_per_day int null check (per_user_per_day is null or per_user_per_day >= 1),
  per_user_per_week int null check (per_user_per_week is null or per_user_per_week >= 1),

  -- 冲突策略（医院很常用）
  conflict_same_shift text not null default 'REJECT'
    check (conflict_same_shift in ('REJECT', 'REPLACE')),
  conflict_overlap_time text not null default 'REJECT'
    check (conflict_overlap_time in ('REJECT', 'ALLOW')),
  conflict_same_type_same_day text not null default 'ALLOW'
    check (conflict_same_type_same_day in ('REJECT', 'ALLOW')),

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## 4.2 签到策略 rule_checkin_policy

```sql
create table rule_checkin_policy (
  rule_set_id bigint primary key references rule_set(id) on delete cascade,

  require_booking boolean not null default true,
  allow_onsite_booking boolean not null default false,
  max_times int not null default 1 check (max_times >= 1),

  audit_log boolean not null default true,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## 4.3 容量与候补（如果你们需要名额/候补）

```sql
create table rule_capacity_policy (
  rule_set_id bigint primary key references rule_set(id) on delete cascade,

  total_capacity int not null default 0 check (total_capacity >= 0), -- 0 表示不限制/或按你们定义
  per_user_capacity int not null default 1 check (per_user_capacity >= 1),

  waitlist_enabled boolean not null default false,
  waitlist_max_size int not null default 0 check (waitlist_max_size >= 0),
  waitlist_promote_policy text not null default 'MANUAL'
    check (waitlist_promote_policy in ('AUTO_PROMOTE_IMMEDIATE', 'MANUAL')),

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

# 5）可选但强烈建议：规则版本与审计（医院场景很需要）

如果你们希望“规则调整可追溯、不影响历史订单”，建议加版本：

## 5.1 rule_set_version（每次发布一版）

```sql
create table rule_set_version (
  id bigserial primary key,
  rule_set_id bigint not null references rule_set(id) on delete cascade,
  version int not null,
  status text not null default 'DRAFT'
    check (status in ('DRAFT', 'PUBLISHED', 'ARCHIVED')),
  published_at timestamptz null,
  note text null,

  created_at timestamptz not null default now(),
  created_by text null,

  unique (rule_set_id, version)
);

create index idx_rule_set_version_status on rule_set_version (rule_set_id, status);
```

然后把 `rule_window/rule_*_policy` 都加一列 `rule_set_version_id`（替代 rule_set_id）即可做到“历史订单绑定某版本规则”。

> 第一版可以不做版本，后面加也行，但要改表/数据迁移。

# 6）示例：配置 10:00–11:00 班次的规则（插入示例）

假设门诊 OPD 的 rule_set_id = 1：

```sql
-- BOOK：提前7天开放，开始前30分钟截止
insert into rule_window (rule_set_id, action, reference_point, open_offset_sec, close_offset_sec, fail_policy)
values (1, 'BOOK', 'SHIFT_START', -604800, -1800, 'REJECT');

-- CHECKIN：开始前10分钟开放，开始后15分钟截止
insert into rule_window (rule_set_id, action, reference_point, open_offset_sec, close_offset_sec, fail_policy)
values (1, 'CHECKIN', 'SHIFT_START', -600, 900, 'REJECT');
```

# 7）命中与校验（后端实现的最小查询）

给定 `shift_type_id`，取生效 RuleSet：

```sql
select rs.*
from rule_set rs
join rule_set_shift_type m on m.rule_set_id = rs.id
where rs.enabled = true and m.shift_type_id = $1
order by rs.priority asc
limit 1;
```

取对应 action 的 window：

```sql
select *
from rule_window
where rule_set_id = $1 and action = $2 and enabled = true;
```

# 8）备选方案 B：JSONB 一表落库（更轻，但不推荐长期用）

如果你们希望配置变更非常频繁、后台页面先不做复杂表单，可以：

```sql
create table rule_set_config (
  id bigserial primary key,
  rule_set_id bigint not null references rule_set(id) on delete cascade,
  config jsonb not null,  -- windows + policies + defaults 全塞进来
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index idx_rule_set_config_gin on rule_set_config using gin (config);
```

但后期想做“必填校验、字段级搜索、差异对比、灰度发布”会比较痛。
