# 服务器端日志查看方法

## 1. SSH 登录服务器

```bash
ssh -i ~/.ssh/github_deploy_key root@106.52.195.26
cd /www/wwwroot/appointment-booking-system
```

## 2. 服务容器说明

| 容器名 | 服务 | 说明 |
|---|---|---|
| `hospital_backend` | backend | FastAPI 主服务，API 请求日志 |
| `hospital_celery_worker` | celery_worker | 异步任务执行日志 |
| `hospital_celery_beat` | celery_beat | 定时任务调度日志 |

## 3. 日志来源与格式

项目有两层日志：

### 3.1 Docker 容器日志（stdout）

- **格式**: JSON（Docker 默认的 json-file 日志驱动）
- **宿主机位置**: `/var/lib/docker/containers/<container-id>/<container-id>-json.log`
- **内容**: 应用输出到控制台的所有日志（含彩色格式化）
- **查看方式**: `docker compose logs` 命令（见下方第 4 节）

### 3.2 应用文件日志（容器内）

应用通过 `app/core/logging.py` 配置了 RotatingFileHandler，在容器内生成日志文件：

| 文件 | 容器内路径 | 内容 | 大小限制 |
|---|---|---|---|
| `hospital.log` | `/app/logs/hospital.log` | 所有级别日志 | 10MB x 5 个轮转 |
| `hospital_error.log` | `/app/logs/hospital_error.log` | 仅 ERROR 及以上 | 10MB x 5 个轮转 |

- **格式**: 纯文本
- **日志格式**: `2025-01-01 12:00:00 | INFO     | module:function:42 | 日志消息`
- **注意**: docker-compose.yml 未将 `logs/` 目录挂载到宿主机，日志文件仅存在于容器内部

## 4. 在线查看日志

### Docker 容器日志

```bash
# 查看 FastAPI 后端日志
docker compose logs backend

# 查看 Celery Worker 日志
docker compose logs celery_worker

# 查看 Celery Beat 日志
docker compose logs celery_beat

# 查看所有服务的日志
docker compose logs

# 实时跟踪日志（类似 tail -f）
docker compose logs -f backend

# 只看最近 100 行
docker compose logs --tail 100 backend

# 带时间戳
docker compose logs -t backend

# 组合使用：实时跟踪 + 只从最近 50 行开始
docker compose logs -f --tail 50 backend
```

### 容器内应用文件日志

```bash
# 查看容器内的日志文件列表
docker exec hospital_backend ls -lh /app/logs/

# 实时查看全量日志
docker exec hospital_backend tail -f /app/logs/hospital.log

# 实时查看错误日志
docker exec hospital_backend tail -f /app/logs/hospital_error.log

# 查看最近 200 行
docker exec hospital_backend tail -200 /app/logs/hospital.log
```

## 5. 拉取日志到本地

### 方法一：导出 Docker 容器日志到本地（推荐用于快速排查）

```bash
# 在本地直接通过 SSH 导出日志到本地文件
ssh -i ~/.ssh/github_deploy_key root@106.52.195.26 \
  "cd /www/wwwroot/appointment-booking-system && docker compose logs --tail 500 backend" \
  > backend.log

# 也可以导出所有服务的日志
ssh -i ~/.ssh/github_deploy_key root@106.52.195.26 \
  "cd /www/wwwroot/appointment-booking-system && docker compose logs" \
  > all-services.log
```

### 方法二：拉取容器内的日志文件到本地（推荐用于完整分析）

**第一步：在服务器上，从容器复制到宿主机**

```bash
# SSH 到服务器后执行
docker cp hospital_backend:/app/logs/hospital.log /tmp/hospital.log
docker cp hospital_backend:/app/logs/hospital_error.log /tmp/hospital_error.log
```

**第二步：在本地，从服务器拉取到本地**

```bash
# 在本地执行
scp -i ~/.ssh/github_deploy_key root@106.52.195.26:/tmp/hospital.log ./hospital.log
scp -i ~/.ssh/github_deploy_key root@106.52.195.26:/tmp/hospital_error.log ./hospital_error.log
```

**一步到位（合并命令）：**

```bash
# 在本地执行，一条命令完成：服务器上 docker cp + scp 拉取
ssh -i ~/.ssh/github_deploy_key root@106.52.195.26 \
  "docker cp hospital_backend:/app/logs/hospital.log /tmp/hospital.log" \
  && scp -i ~/.ssh/github_deploy_key root@106.52.195.26:/tmp/hospital.log ./hospital.log

ssh -i ~/.ssh/github_deploy_key root@106.52.195.26 \
  "docker cp hospital_backend:/app/logs/hospital_error.log /tmp/hospital_error.log" \
  && scp -i ~/.ssh/github_deploy_key root@106.52.195.26:/tmp/hospital_error.log ./hospital_error.log
```
