# 桌面客户端安装与配置指南（机构）

适用于医院挂号系统的两个桌面客户端：**HospitalAdmin（机构管理端）** 与 **HospitalDoctor（医生端）**。桌面客户端的业务与网页版完全一致，仅是独立窗口的安装形态；后端地址按机构配置，无需重新打包。

## 1. 下载安装

从运营方提供的发布页（GitHub Release 或运营方分发的安装包）获取：

| 平台 | 文件 | 说明 |
|---|---|---|
| Windows x64 | `*_<版本>_x64-setup.exe` | 双击安装；更新采用 NSIS 静默模式 |
| macOS（Intel/Apple 芯片通用） | `*_<版本>_universal.dmg` | 拖入「应用程序」即可，两种芯片通用 |

**macOS 首次打开提示"无法验证开发者"**（未签名阶段）：在「应用程序」中**右键 → 打开 → 再点打开**，仅需一次。后续自动更新不受影响。

安装一次即可：**升级后端地址配置（第 2 节）与已登录状态在升级时都会保留**。

## 2. 配置机构后端地址（必需）

客户端安装时不内置任何后端地址，首次使用前按机构配置一次：

**配置文件位置**（目录名固定，随应用自动创建）：

- macOS：`~/Library/Application Support/online.aicm.hospital.admin/`（医生端为 `...hospital.doctor/`）
- Windows：`%APPDATA%\online.aicm.hospital.admin\`（医生端为 `...hospital.doctor\`）

在该目录创建 `desktop-config.json`，内容（注意键名是**顶层扁平键**，两侧引号不可省）：

```json
{"desktop.baseUrl": "https://yy.aicm.online/api/v1"}
```

保存后**重启应用**生效。未配置时：网页版不受影响；桌面端启动会弹出配置指引。写入嵌套形式 `{"desktop": {"baseUrl": …}}` 也兼容。配置错误的典型现象是登录页一直提示「网络连接失败」——回来核对本节。

## 3. 自动更新

客户端启动约 5 秒后静默检查更新；发现新版本会弹出**更新公告 + 一键更新**，下载安装完成后询问是否重启（**不会**自动重启，避免打断挂号/排班操作）。

- 更新源在生产站点（`https://yy.aicm.online/desktop/updates/…`），国内网络直连可达；
- **纯内网机构**（无法访问公网）自动更新会静默跳过，由运营方分发新安装包手动升级即可，已配置的后端地址不会丢失。

## 4. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 登录页一直「网络连接失败」 | 第 2 节未配置或键名写错；确认扁平键 `"desktop.baseUrl"` 后重启 |
| 提示「桌面端尚未配置后端地址」弹窗 | 同上 |
| macOS 提示无法验证开发者 | 第 1 节的右键打开方式 |
| 重复点击图标没有开出第二个窗口 | 设计如此：单实例，自动聚焦已有窗口 |
| 升级后版本没变 | macOS 下选择「稍后重启」后需手动退出再打开才生效 |
| 头像/上传的图片不显示 | 已知限制（桌面端图片走相对路径），不影响业务功能，修复排期中 |

## 5. 版本与发版

版本号两端锁步（同一 tag 同时发布），发版与更新源维护流程见 [`desktop-release/README.md`](../desktop-release/README.md)。
