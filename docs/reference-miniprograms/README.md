# 竞品小程序参考：三家中医诊所小程序（百医可依模板）

> 2026-10-22 通过微信桌面端「搜一搜」实际打开三家小程序逐页截图所得。截图存于本目录下三个子文件夹。

## 核心结论

1. **三家小程序是同一套 SaaS 白标模板**，页脚均显示「技术支持：百医可依」。差异仅为换肤级：主题色、logo、门店照片、公告文案、医生数据、少量菜单项。
2. 模板结构简单：**3 个 tab（首页 / 机构中心(简介) / 我的）+ 首页四宫格入口 + 推荐医生列表**。
3. 本仓库的 `apps/patient-miniapp`（Taro 4 + NutUI）已覆盖该模板全部可见功能，且能力远超（排班、就诊人管理、随访、候补、签到等）；`apps/miniapp-generator` 已具备按租户生成小程序的壳（shells: home / department / doctor / appointment / profile）。**复刻主要是租户级配置工作，而非新功能开发。**

### 预约流程结论（与现有 patient-miniapp 的差异）

1. 竞品是「日期 → 医生（带号源标签）→ 半天时段 → 确认页」四步，**没有独立科室选择页**（医生卡片上直接标科室）；本仓库是「科室 → 医生 → 时间轴」，功能更细。
2. 竞品时段粒度是**半天（上午 09:00-12:00 / 下午）**，标签文案「专属(余N)」；本仓库支持到具体时间片，属超集。
3. 确认页关键要素：挂号费（初诊价）、就诊地点、病情主诉必填、注意事项、就诊人切换。复刻时应照此布局。
4. 医生详情页有「医生海报」分享图（logo+医生头像/擅长/简介+小程序码）和「患者评价(N)/写评价」模块；医生详情底部即评价区。
5. 竞品的挂号是「先线上占号，医助线下确认到店时间」的轻流程，没有线上支付环节（费用到店支付，确认页只展示价格）。

### 本次仍缺的界面

- 「确认预约」后的预约成功/详情页（为避免真实占用诊所号源，未提交订单）。
- 三草堂、颐寿清两家的登录后页面（登录态按小程序独立，需要分别登录）。
- 颐寿清机构中心的 5 个二级入口子页（科室介绍/医生介绍/设备展示/科室分布/机构环境）。
- 「联系我们」（桌面端点击无界面表现，疑似直接拉起拨号）。

> 操作备注：桌面端小程序 webview 不响应合成滚轮事件，但点击页面聚焦后按方向键可以滚动；「医生海报」桌面端点击无响应，需在手机端查看/保存。

## 复刻落地建议

1. **租户配置对齐**：在 `apps/miniapp-generator` 的租户配置中支持/补齐——logo、主题色、首页 banner 图与文案、公告栏文字、机构介绍富文本、门店列表（地址/电话/照片）、健康卡卡片文案。
2. **四宫格入口映射**：预约挂号 → `packageBooking/pages/booking`；预约记录 → `pages/appointment`；我的就诊卡 → `packageProfile/pages/patient`；在线客服 → 需新增（webview 客服或微信客服会话）。
3. **首页模块顺序**固定为 banner → 公告 → 四宫格 → 健康卡 → 推荐医生，推荐医生卡片加「有号」标签。
4. **机构中心**按「照片 + 联系方式 + 可选二级入口 + 富文本介绍」做成配置化模块。
5. **合规**：可复刻页面结构与交互；不得直接使用百医可依的图片素材、图标与代码。医生头像、门店照片等需诊所方提供。
