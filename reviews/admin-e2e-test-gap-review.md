### Designer — 用户视角

**路由清单：**
- 6 个一级菜单，68+ 页面路由（含隐藏路由 111 个）
- 隐藏路由：新增/编辑表单页、详情页
- 特殊路由：登录页、租户停用页、个人设置页、404 页

**关键用户操作流（按模块）：**
1. 医生管理：搜索筛选 → 拖拽推荐排序 → 新增/编辑（30+ 字段）→ 诊费设置弹窗 → 删除
2. 预约管理：多条件筛选 → 查看详情 → 取消预约（输入原因）→ 退款流程（Drawer）
3. 排班管理：规则设置 → 日历/甘特图视图 → 自定义排班 → 停诊管理 → 统计
4. 科室管理：拖拽排序 → 推荐开关 → 热门开关 → 绑定医生弹窗 → 状态切换
5. 租户管理：激活/暂停 → 订阅计划管理 → 状态管理

**表单校验规则（18 种）：**
- 必填、格式（手机号/邮箱/URL/身份证/用户名）、长度、数值范围
- 唯一性验证（异步，防抖 500ms，医生账号/门店编码/租户标识）
- 密码强度（弱/中/强）、确认密码一致性
- 条件验证（根据其他字段值决定是否校验）

**交互模式：**
- Modal（800px/900px）→ Drawer（480px）→ Popconfirm 三层确认
- Switch 实时状态更新（onChange 直接调 API）
- 拖拽排序（@dnd-kit/core）
- 导入导出（Upload.Dragger + 结果 Table）

**空/异常状态处理：**
- 空列表：Empty 组件 + 描述文字
- 加载中：Spin + Skeleton（6 行）
- API 错误：message.error 全局提示
- 401：跳转登录页，清除 Token
- 403：菜单隐藏 + 按钮不渲染
- 404：独立页面

## Round 2：辩论层

### 交叉评论投票矩阵

#### 简化投票矩阵（集中调度模式）

| 议题 | 裁决者立场 | Critic 质询 | 最终裁决 |
|------|-----------|------------|---------|
| 烟雾测试"100%覆盖" | 修正为 57%（63/111） | 🚨 虚假安全感 | P1：扩展隐藏路由烟雾测试 |
| 创建操作最高优先 | 同意，但编辑/删除同等重要 | 普通 | P0：补齐编辑/删除 |
| 表单校验需覆盖 | 唯一性+必填最高优先 | 普通：18种不需全测 | P1：只测高业务风险校验 |
| 权限测试需独立策略 | SaaS 核心风险 | 🚨 被三方遗漏 | P0：权限边界测试 |

| CI 集成 | 先补测试再接 CI | 普通 | P1：测试就绪后接 CI |

### 独到发现

1. 烟雾测试实际仅覆盖 57% 路由（63 可见 vs 111 全部），48 条隐藏路由（表单页/详情页）未覆盖
2. Mock 层（52 端点）基础设施完备但利用率极低——804 行辅助代码仅支撑 13 个用例
3. 测试代码 292 行 vs 辅助代码 804 行（1:2.75），基础设施投入大但利用率低
4. 没有任何编辑操作测试，意味着最频繁的管理操作完全未覆盖
5. 权限测试被三方都低估——对 SaaS 多租户系统这是最高风险场景

### Critic 质询（12 条，3 条关键）

1. 🚨 **烟雾测试"100%覆盖"是虚假安全感**：63 vs 111 路由矛盾，48% 路由未覆盖
2. 普通：模块依赖链未对应测试优先级，排班/预约是核心但测试断裂
3. 普通：18 种校验规则不需全测，需区分前端校验和业务风险
4. 普通：0% 覆盖率的计算基准不清晰（独立测试 vs 间接覆盖）
5. 🚨 **全 Mock 策略导致测试价值存疑**：无法验证 API 契约变更
6. 🚨 **权限测试被遗漏但这是 SaaS 核心风险**：3 角色 30+ 权限 0% 覆盖
7. 普通：交互模式测试成本未评估（拖拽/Switch ROI）
8. 普通：111 个路由中有多少是低频配置页面可降级
9. 普通：并发/兼容性/性能/可访问性被三方遗漏
10. 普通：292 行测试 vs 804 行辅助代码倒挂
11. 普通：CRUD 完整度标注与测试优先级不匹配
12. 普通：优先级划分缺乏数据支撑

## Round 3：共识层

### ✅ 共识项

1. **烟雾测试覆盖不足**
   **结论：** 实际仅覆盖 57% 路由，需扩展至隐藏路由并验证页面核心内容
   **建议行动：** 新增隐藏路由烟雾测试，验证表单页/详情页可打开且核心元素可见
   **成本估算：** 4h
   **优先级：** P1

2. **编辑/删除操作完全未测试**
   **结论：** 最频繁的管理操作零覆盖，是最大测试缺口
   **建议行动：** 为核心模块（医生/科室/门店/租户/角色）补齐编辑和删除测试
   **成本估算：** 8h
   **优先级：** P0

3. **权限边界测试是 P0**
   **结论：** SaaS 多租户系统权限越界 = 数据泄露，3 角色 30+ 权限 0% 覆盖
   **建议行动：** 新增 STORE_ADMIN/STORE_USER mock 数据，测试菜单/按钮/数据三级隔离
   **成本估算：** 12h
   **优先级：** P0

4. **表单校验测试聚焦高业务风险项**
   **结论：** 18 种校验不需全测，优先覆盖唯一性（医生账号/门店编码/租户标识）和必填项
   **建议行动：** 为含唯一性校验的表单新增校验测试
   **成本估算：** 6h
   **优先级：** P1

5. **状态流转测试缺失**
   **结论：** 启用/禁用、发布/草稿等状态切换操作零覆盖
   **建议行动：** 覆盖科室/医生/租户/内容的启用禁用和内容发布草稿
   **成本估算：** 4h
   **优先级：** P1

6. **搜索筛选/分页测试缺失**
   **结论：** 列表页核心交互零覆盖
   **建议行动：** 为预约列表（最复杂筛选）和医生列表（拖拽排序）补测试
   **成本估算：** 4h
   **优先级：** P1

7. **异常处理测试缺失**
   **结论：** API 失败、空数据、401 跳转场景零覆盖
   **建议行动：** 新增 API 错误 mock，验证错误提示和 401 重定向
   **成本估算：** 3h
   **优先级：** P1

8. **CI 集成待测试就绪后配置**
   **结论：** 先补测试再接 CI，避免 CI 运行低价值测试
   **建议行动：** 测试达到 50+ 用例后配置 GitHub Actions E2E workflow
   **成本估算：** 3h
   **优先级：** P2

9. **Mock 契约校验**
   **结论：** 全 mock 策略合理但需校验 mock 数据与 API schema 一致
   **建议行动：** 新增契约测试，验证 mock 响应与 OpenAPI schema 匹配
   **成本估算：** 6h
   **优先级：** P2

### ⚡ 分歧项

1. **排班管理模块测试深度**
   **各方立场：**
   - PM：排班是核心依赖链节点，需深度测试
   - Designer：排班有 12 个路由、多视图、复杂规则配置，测试成本极高
   - Engineer：排班规则表单 1706 行，是最复杂的页面
   **裁决：** P1 覆盖规则列表可达性 + 规则创建，排班日历/甘特图交互降为 P2
   **决策依据：** ROI 平衡——规则是数据源头，日历/甘特图是展示层

2. **导入导出测试优先级**
   **各方立场：**
   - PM：9 个模块支持导入导出，使用频率高
   - Engineer：导入导出组件已封装为共享组件，单元测试可覆盖核心逻辑
   **裁决：** P2——为导入导出组件写 1 个通用测试即可，不需每个模块重复测试
   **决策依据：** 共享组件测试一次覆盖全部模块

## 被低估的优势

1. **Mock 基础设施已非常完备**：52 个 API 端点全 mock，辅助函数封装良好，新增测试成本低
2. **循环测试模式**：烟雾测试使用循环遍历路由，新增路由自动覆盖，维护成本极低
3. **测试数据生成策略成熟**：Date.now() 时间戳避免冲突，动态生成可读名称

### P0：立即执行（高价值、关键风险）

1. **权限边界测试（12h）**
   - 新增 STORE_ADMIN / STORE_USER mock 数据

   - 测试数据隔离：门店用户只能看到自己门店的数据

2. **核心 CRUD 编辑/删除测试（8h）**
   - 医生编辑（30+ 字段修改 + 保存验证）

   - 租户编辑 + 激活/暂停
   - 角色编辑 + 权限分配

1. **表单校验测试（6h）**：唯一性（医生账号/门店编码/租户标识）、必填项、手机号格式

3. **状态流转测试（4h）**：科室/医生启用禁用、内容发布草稿、租户激活暂停
4. **搜索筛选测试（4h）**：预约列表多条件筛选、医生列表搜索+门店联动
5. **异常处理测试（3h）**：API 500/401/403 错误提示、空列表展示、网络超时
6. **CI 配置（3h）**：GitHub Actions E2E workflow，失败截图+trace 上传

### P2：下个周期规划（中等价值、较高成本）

1. **排班高级视图测试（4h）**：日历视图交互、甘特图渲染、自定义排班流程

### 待定：需用户确认
