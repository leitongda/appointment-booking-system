## 建议实施顺序

### 第一批（P0，~20h）

1. **权限边界测试**（12h）——SaaS 核心风险
   - 新增 STORE_ADMIN / STORE_USER mock 数据和 session
   - 9 项权限测试全覆盖

2. **核心模块编辑/删除**（8h）——最频繁操作
   - 医生/科室/门店/租户/角色的编辑和删除
   - 包含二次确认、列表刷新验证

### 第二批（P1，~24h）

1. 表单校验（6h）——唯一性 + 必填 + 格式
2. 隐藏路由烟雾测试（4h）——48 条隐藏路由
3. 状态流转测试（4h）——启用/禁用 + 发布/草稿
4. 搜索筛选测试（4h）——预约列表 + 医生列表
5. 异常处理测试（3h）——API 错误 + 空数据 + 401
6. CI 配置（3h）——GitHub Actions E2E workflow

### 第三批（P2，~12h）

1. 排班高级视图测试（4h）
2. Mock 契约校验（6h）
3. 导入导出通用测试（2h）
4. 其余 P2 项按需补充

## 测试基础设施建议

1. **新增 data-testid**：为关键操作元素添加 `data-testid` 属性，提高选择器稳定性
2. **角色 mock 工厂**：封装 `createMockUser(role, permissions)` 工厂函数
3. **API 错误 mock**：新增 `mockApiError(endpoint, statusCode)` 辅助函数
4. **测试数据生成器**：封装 `generateTestData(module, overrides)` 统一数据生成
5. **Page Object 模式**：为核心模块创建 Page Object 封装常用操作
