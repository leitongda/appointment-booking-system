## ADDED Requirements

### Requirement: Admin 端角色分配页必须按控制类型解释权限
系统 SHALL 在 Admin 端角色分配页中，将权限以更符合管理认知的控制类型进行展示，至少包括页面、Tab/视图、按钮/操作、接口/数据能力四类。

#### Scenario: 管理员查看某个角色的权限
- **WHEN** 管理员进入角色的“分配权限”页面
- **THEN** 系统应展示每个权限对应的控制类型标签
- **AND** 控制类型至少包含页面、Tab/视图、按钮/操作、接口/数据能力
- **AND** 管理员不需要只依赖 `menu/button` 才能理解权限含义

#### Scenario: 权限本身仍沿用现有权限码
- **WHEN** 系统展示新的控制类型
- **THEN** 不应要求管理员重新定义现有权限码
- **AND** 系统应保持现有角色权限存储结构与接口协议兼容

### Requirement: 角色分配页必须支持按模块与类型快速筛选权限
系统 SHALL 允许管理员通过模块和控制类型快速定位权限，降低逐层展开树结构的操作成本。

#### Scenario: 管理员只想查看接口类权限
- **WHEN** 管理员在分配页选择“接口/数据能力”筛选
- **THEN** 系统应只展示该类型的权限项或分组

#### Scenario: 管理员搜索某个权限
- **WHEN** 管理员输入权限名或权限码关键字
- **THEN** 系统应返回匹配的权限项
- **AND** 未匹配的模块或权限组不应继续占据主要视图空间

#### Scenario: 管理员只查看已选权限
- **WHEN** 管理员启用“仅看已选”
- **THEN** 系统应只展示当前角色已勾选的权限
- **AND** 仍应保留其所属模块和控制类型上下文

### Requirement: 角色分配页必须提供批量选择与实时摘要
系统 SHALL 支持面向权限分组的批量选择，并在操作过程中实时反馈已选概况。

#### Scenario: 按模块全选权限
- **WHEN** 管理员对某个业务模块执行“全选”
- **THEN** 系统应一次性勾选该模块下所有权限
- **AND** 已选数量和模块覆盖数应立即更新

#### Scenario: 按类型批量选择权限
- **WHEN** 管理员选择“全选按钮/操作类权限”
- **THEN** 系统应勾选当前可见范围内该类型的全部权限

#### Scenario: 查看角色权限摘要
- **WHEN** 管理员调整权限勾选状态
- **THEN** 系统应实时展示已选权限总数、已覆盖模块数和各控制类型数量

### Requirement: 权限分配保存流程必须保持现有鉴权协议兼容
系统 SHALL 在重构 Admin 端权限分配交互后，继续以现有权限码数组与后端保存接口对接。

#### Scenario: 保存权限
- **WHEN** 管理员点击保存
- **THEN** 前端提交给后端的数据仍应是权限码数组
- **AND** 现有角色权限更新接口无需因展示分类变化而调整请求协议

#### Scenario: 保存失败
- **WHEN** 后端返回保存失败
- **THEN** 系统应保留当前勾选状态
- **AND** 管理员不应被迫重新选择权限
