## Context

当前仓库已经具备以下基础：
- 患者端小程序存在较完整业务能力，可作为业务内核基线
- 已有 `add-template-driven-miniapp-platform` 变更，正在引入模板、实例、支付配置和发布能力
- 当前模板方向更偏“实例与发布治理”，尚未清晰定义“多风格前端壳层”的表达方式

本次设计目标是在现有方向上补齐“模板如何表达明显不同的小程序体验”。

## Goals / Non-Goals

**Goals:**
- 支持同一套业务逻辑生成多套体验差异明显的小程序
- 允许模板定义导航结构、首页模块树、页面壳层和视觉系统
- 第一阶段提供 5 套高质量预制模板
- 保持后端接口、交易状态、核心业务结果一致
- 为第二阶段“模板 + 配置混合”保留升级路径

**Non-Goals:**
- 本次不开放任意页面自由拼装
- 本次不改变预约、支付、签到等核心状态流转
- 本次不尝试由 AI 动态实时生成整个前端应用
- 本次不要求一次性完成所有模板的后台可视化编辑器

## Decisions

### 1. 采用四层结构

平台采用四层结构：
- 业务内核层
- 页面壳层层
- 模板定义层
- 实例生成层

这样可以把“业务逻辑”和“风格体验”解耦。

### 2. 第一阶段使用预制模板，而非完全配置驱动

第一阶段优先交付 5 套预制模板，原因是：
- 质量更可控
- 差异更容易做深
- 更适合外部销售和交付展示

第二阶段再演进到模板 + 配置混合。

### 3. 模板必须同时表达视觉与信息架构

模板不能只包含颜色、字体、图标。

模板必须至少表达：
- 底部导航结构
- 首页模块树
- 页面壳层变体
- 视觉 token
- 默认文案语气
- 不可突破的业务边界约束

### 4. 页面壳层允许变化，业务页面协议保持稳定

每个业务页面应拆分为：
- 业务容器：负责数据获取、动作提交、状态处理
- 页面壳层：负责布局、模块顺序、视觉表达

模板切换时，优先切换页面壳层而不是重写业务逻辑。

### 5. 第一阶段固定 5 套模板家族

第一阶段的模板家族固定为：
- 现代综合医疗
- 高端专科门诊
- 亲子儿科
- 女性健康
- 长辈友好 / 中医康养

其价值在于覆盖“通用医疗、品牌专科、家庭场景、女性场景、长辈康养”五类典型销售场景。

## Template Model

建议模板定义最少包含以下内容：

```ts
interface MiniappStyleTemplate {
  code: string;
  name: string;
  category: string;
  supportedAudience: string[];
  navSchema: NavSchema;
  homeSchema: HomeModuleSchema[];
  pageShellBindings: Record<string, string>;
  designTokens: DesignTokenSet;
  assetPack: AssetPack;
  copyTone: CopyToneConfig;
  constraints: TemplateConstraints;
}
```

其中：
- `pageShellBindings` 决定某个业务页面使用哪一套壳层
- `constraints` 用于声明某些页面不可被替换或不可改变动作顺序

## Variant Boundary

### High-variance areas

- 首页
- 个人中心首页
- 科室与医生展示页
- 导航结构
- 卡片和模块编排

### Low-variance areas

- 预约确认页
- 支付结果页
- 签到流程页
- 消息读写动作
- 设置功能页

这样既能保证风格差异明显，也能降低交易链路风险。

## Generation Flow

第一阶段推荐生成流程：

1. 在后台创建小程序实例
2. 选择模板和模板版本
3. 配置实例品牌、AppID、默认门店、支付配置
4. 写入实例与模板绑定关系
5. 构建时注入模板代码、模板版本、实例 ID
6. 构建器根据模板定义装配页面壳层和资源包
7. 输出实例级可发布产物

## Rollout Plan

### Phase 1
- 明确业务内核与页面壳层边界
- 定义模板数据结构
- 完成 1 套基线模板与 1 套强差异模板验证

### Phase 2
- 补齐 5 套模板
- 在实例管理中接入模板选择
- 在构建流程中记录模板版本

### Phase 3
- 开放部分模块级配置能力
- 升级为模板 + 配置混合模式

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 模板差异做得不够，只变颜色不变体验 | 强制模板包含导航、首页模块树和页面壳层定义 |
| 页面壳层过度自由，导致交易链路回归风险高 | 固定交易链路页面和核心动作协议 |
| 第一阶段直接做配置驱动导致系统过重 | 先预制模板，后混合配置 |
| 模板数量上来后维护成本高 | 建立统一模板元数据结构和共享业务容器 |
